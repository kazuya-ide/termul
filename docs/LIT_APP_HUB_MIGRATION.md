# LIT App Hub — 既存アプリ移行の検討(Phase 0)

作成日: 2026-07-27
状態: **Phase 0〜MVPでは移動は一切行わない。** 本書は将来アプリを`C:\LIT-Workspace\...`のような標準ルートへ移す判断をする際に使うチェックリストの雛形。

---

## 1. MVPでの方針

依頼書9章・10章のとおり、現時点では:

- 検出・登録したアプリの`projectPath`/`workspacePath`は**現在の実際のパスをそのまま**保存する。
- フォルダの移動・改名・削除は**井手さんの明示的な承認なしに一切行わない**。
- 標準ルート案(`01_COMPANY` 等)は「将来こうすると整理しやすい」という提案であり、強制しない。

## 2. 将来、個別アプリを移動する場合のチェックリスト(1アプリにつき1回埋める想定の雛形)

| 項目 | 内容 |
|---|---|
| アプリ名 | (ManagedApp.name) |
| 現在の場所 | |
| 推奨移動先 | |
| 移動で壊れる可能性のあるパス | 絶対パス参照がある設定ファイル・スクリプト・ショートカット等を列挙 |
| `.env`への影響 | `.env`内に絶対パス参照が無いか確認。あれば移動後に手動更新が必要 |
| Gitへの影響 | `.git`ディレクトリごと移動すれば通常は問題ないが、`.git/config`にsubmodule等の絶対パスが無いか確認。リモートURLは影響なし |
| Node.jsへの影響 | `node_modules`はパス非依存で動くことが多いが、一部ネイティブアドオンやシンボリックリンク(monorepoのworkspace等)はパス変更で壊れる場合がある。安全のため移動後に`npm/bun install`をやり直すことを推奨 |
| Python仮想環境への影響 | `.venv`は**多くの場合、内部に絶対パスを埋め込んでいるため移動すると壊れる**。移動する場合は`.venv`を再作成することを前提にする |
| データ参照への影響 | アプリがSQLite等のローカルDBファイルを相対/絶対パスで参照していないか確認 |
| ショートカットへの影響 | デスクトップショートカット・タスクバー固定・`.vscode/*.code-workspace`のパス指定を再作成する必要がある |
| 移動後の確認方法 | ①アプリ起動 ②devサーバー起動 ③ローカルURLでの表示確認 ④Git操作(status/commit)の3点は最低限確認する |
| ロールバック方法 | 移動前にフォルダを丸ごとコピー(移動でなく)しておき、問題があれば元の場所のコピーに戻す。ManagedApp側の`projectPath`も元に戻す |

## 3. 標準ルート案(依頼書9章、参考として転記)

```text
C:\LIT-Workspace\
├─ 01_COMPANY\
├─ 02_PERSONAL\
├─ 03_SNS\
├─ 04_AUTOMATION\
├─ 05_SHARED_DATA\
├─ 06_ARCHIVE\
└─ 99_UNKNOWN\
```

この構成を採用するかどうか、採用する場合の対象アプリの優先順位は、MVPで実際にアプリを20件以上登録して全体像が見えた後に、改めて判断することを推奨する(依頼書21章の「最初は3〜5個で検証」という段階的方針とも整合する)。
